# AF8 prior の設計（結果を見る前に固定）

## 1. 生成器が loading をどう作っているか（FACT、一次ソース）

ソースは `data_generator_multisupport.py:52-75` と `data_generator_canonical.py:127-165`。

```
G ~ N(0,1)^{d×K}  →  Q R = G（reduced QR、diag R > 0 になるよう符号を固定）
F = Q · diag(row_scale),   row_scale_l = sqrt(τ_l · d / K / A''_{true,l}(0))
```

- 設定は d = 9、K = 3、count 列の τ_l = 2。A''_P(0) = 1、A''_C(0) = 0.51311。
- Q は Stiefel 多様体上の一様分布に従う。各行 q_l は R^K で等方的で、‖q_l‖² ~ Beta(K/2, (d−K)/2) = Beta(1.5, 3)、平均は K/d = 1/3。
- したがって次が成り立つ。
  - 標準化した loading g_l = √A''_{true}(0) f_l の 2 次モーメントは E[g_l g_lᵀ] = (τ/K) I = (2/3) I。
  - ただし ‖g_l‖² = 6·Beta(1.5, 3) ≤ 6 で、**Gaussian ではない**（N(0, 2/3 I) なら ‖g‖² ~ (2/3)χ²_3 で上限がない）。
  - 9 行は同じ Q から作るので独立ではない。ただし 1 列だけを見る局所的な比較には影響しない。

## 2. 比べる 2 種類の prior

| prior | f_j の分布 | 性質 |
|---|---|---|
| A：loading そのものに共通の Gaussian | N(0, s I)（候補によらない） | 平均が同じなら CMP2 の loading は Poisson のおよそ 2 倍のスケールになる。そのため A は CMP2 の f を相対的に強く縮め、Poisson 側への縮小の偏りを作る。s → ∞ で候補間の prior の差は消える。 |
| B：Fisher 情報で標準化した loading に共通の prior | g = √a_m f ~ N(0, s I)、つまり f ~ N(0, (s/a_m) I)、log p には Jacobian (K/2) log a_m を含む | どちらの候補でも「η=0 での列の期待 Fisher 情報 a_m E‖f‖²」が同じ分布になる。候補に中立な原理である。ただし s → ∞ でも Δ には (K/2) log(a_C/a_P) = −1.00 が残る（mathematical_derivation.md §1.1）。 |

## 3. 主設定とその理由

**主設定は B、s = 2/3。**

- 選んだ理由:
  - 候補ごとの情報スケールをそろえる原理（B）は、生成器と同じ標準化である。
  - s = τ/K は生成器の設計値で、2 次モーメントが一致する。
- 真のラベルも、AF6 での正解率も使っていない。
- ただし、これは**シミュレーション設計を知っていること**による設定なので、実データにはそのまま当てはめられない。この限界を明記する。
