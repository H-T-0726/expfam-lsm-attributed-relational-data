- pilot の範囲は rep01〜rep03（AF6 データ）、dense と sparse、count 列 6 本、2 候補、prior 9 種類で、合計 648 セル。
- コードと protocol の版:
  - commit `0060b16`（protocol sha256 `5c8f4b2e…5815`）
  - driver だけの変更 `a37584b`（collect を shard から分離）
  - 各 shard の runinfo は `pilot/runinfo_*.json`

- **pilot では正解率と選択結果を計算していない。** E と IS の符号の一致数は、ラベルを使わない数値の比較である。

## 3. 原因（`pilot/pilot_failure_diagnosis.json`、`analyze_af8_integrated_loading.py --pilot-diagnose`）

3 つの事象はいずれも、**最適化の安全装置の欠陥**による。選択基準そのものの性質ではない。

### (a) joint Newton が鞍点に収束した（E の開始点の不一致 約 600〜1190）

- rep01 sparse 列 3（真 Poisson、x の最大 86、平均 3.8）で、f = 0 から始めた `mode_u` は、勾配 1e-14 の停留点 f ≈ (0.03, 0.02, 0.12) に収束した。
- その点での負の Hessian は **負の固有値を 3 個**持ち（最小 −72.6、CMP2 では −83.9）、**極大ではなく鞍点**である。Ψ は大域的な最大より 600〜1190 低い。
- ほかの開始点（anchor の plug-in、AF6 の f_L）は同じ点に収束し、そこでは正定値だった（最小固有値 1.49 / 1.38）。
- 原因: `mode_u` は Newton 方向で ⟨step, g⟩ > 0 だけを確認しており、H が正定値かどうかを保証していない。
- 選択には Ψ が最大の開始点を使うので E の値そのものは正しいが、規則上は不一致として数えられた。

### (b) BFGS が極端な f で S を評価した（Poisson で 22 セルが FAILED。20 件は eigvalsh、2 件は Singular matrix）

- 同じ列 3（rep01 sparse、rep03 sparse・dense）で、手法 D の BFGS 実行中に、S の評価から `LinAlgError` が送出された（eigvalsh 20 件、`modeZ` の solve による Singular matrix 2 件）。
- S が −∞ を返さず例外を送出したため、セル全体が FAILED になった。trace は scipy の直線探索（amax = 1e100）の中を指している。
- **「exp(η) が非有限になった」ことを直接示す記録はない**（独立監査 W2）。考えられる経路は次の 2 つ（**未検証**）。
  - (i) `modeZ` と `mode_u` は直線探索が失敗しても最後の試行点を採用するので、NaN が伝わった。
  - (ii) T の番兵の値 −1e300 と、有限差分による勾配が組み合わさって勾配が約 1e304 になり、BFGS が極端な f に飛んだ。
- 失敗は、重い裾を持つ 1 列（x の最大 86）の Poisson 候補だけに偏っている。「候補が合わないことによる失敗ではない」とは示せていない。再実行でもこのまま Q に戻すと、**候補とデータに依存した欠測**になる。

### (c) D の zero 開始点では、Z だけの問題が凹でない（不一致 1e300 は番兵の値）

- rep02 sparse 列 8 では、f = 0 だと内側の Z の mode が見つからなかった（勾配 0.28、H_ZZ の最小固有値 −0.010）。
- これは、対象列が情報を持たないとき、Y の項（w > 0）によって Z の問題が凹でなくなるためである。
- このとき S = −∞ となり、BFGS の目的関数が番兵の値 1e300 を返した。それが「開始点の不一致 1e300」として記録された。
- ほかの開始点どうしの不一致は 1e-12 以下だった。

## 4. 近似の精度（通過した部分。主 prior、両候補とも OK の 33 列）

| 比較（Δ の水準） | 中央値 \|差\| | 範囲（最小〜最大） | 符号の一致 |
|---|---|---|---|
| E（同時 Laplace）− IS | 0.19 | −1.18 〜 +0.70 | 32/33 |
| E2（nested Laplace）− IS | 0.017 | −0.042 〜 +0.066 | 33/33 |

- IS の Δ の MC SE は中央値 0.025、ESS の最小は 342/400。
- **注意（独立監査 W5）：IS は E2 と同じ被積分関数 exp T（Z は Laplace）を使い、proposal も E2 の Hessian から作っている。** そのため、E2 と IS の一致は構成上ほぼ当然で、IS は (Z, f) の厳密な積分の参照値ではない。
- E − IS（中央値 0.19、最大 1.18）は E の誤差の上限ではなく、2 つの近似の差である。AF6 の TI で見た Z の Laplace 誤差（中央値 −0.12）と同じ桁なので、**E と E2 のどちらが厳密な値に近いかは、この pilot では判定できない。**
- この 33 列は、重い裾の列 3 を FAILED として除いた後の列である。
- mathematical_derivation.md §2.2 で述べたとおり、E は Z の体積項の f への依存を 2 次までしか取り込まない。E2 と IS は、その依存を各 f で評価している。
- Z の Laplace 誤差（AF6 の TI では Δ の中央値 −0.12）は、E・E2・IS のすべてに共通して残る。
- 計算時間は、1 セルの中央値が主 prior で 16 秒（E2 と IS を含む）、それ以外で 5 秒。pilot 全体の CPU 時間は 1.45 時間。

## 5. 再実行する場合に必要な修正（Human Gate。実装も実行もしていない）

1. `mode_u` と `modeZ` を、直線探索が失敗したら移動しない形にする。H が正定値でなければ修正 Newton（固有値の下限処理、または信頼領域）に切り替え、鞍点に収束しないようにする。
2. S、E、T の評価で、非有限値と `LinAlgError` を捕捉し、例外ではなく −∞ を返す。BFGS の直線探索の範囲を制限する。
3. 開始点の不一致の規則を、「どの開始点も正定値の停留点に到達したうえで、Ψ の最大と 2 番目の差」に定義し直す。鞍点や番兵の値は、別に記録する。
4. 主となる近似を E と E2 のどちらにするかは、Human Gate で事前に決め直す。
   - pilot で E2 が IS に近かったのは、上に書いたとおり構成上の理由による。
   - pilot のデータ（rep01–03）は本実験の 40 データに含まれ、AF6 で真のラベルも分かっている。pilot を見たうえで決めたことは開示する。
5. 開始点の不一致の閾値（1e-6）、分母（9 種類の prior すべての行）、D と E の最大を取ることは、コード（`analyze_af8_integrated_loading.py`）でしか定義されておらず、protocol.json には書かれていなかった。
   - 規則 `fd_rel_err_max` は、pilot_audit では評価していない。
   - 再実行するなら、これらを protocol に明記する。
6. そのほかの欠陥（独立監査 W3）も直す。
   - E は、収束や正定値かどうかを確かめずに Ψ が最大の開始点を選んでいる。
   - D は `res.success` を記録していない。
   - IS は、非有限の draw を除いた数で割っているので、上方バイアスが生じうる。
   - T は warm start があるため、評価の順序に依存する。

これらは protocol の変更にあたるため、結果を見る前の事前登録として、もう一度凍結する必要がある。
