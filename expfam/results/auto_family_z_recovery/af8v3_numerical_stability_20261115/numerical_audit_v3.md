## 3. E・E2・IS の差（診断、主スコアは E2）

**E2 と IS（主 prior の 36 対）**
- median |ΔE2 − ΔIS| は 0.0124、最大は 0.065。
- IS の標準誤差で割った値は、median 0.52、最大 2.5。
- 符号の不一致は 0/36。
- 最大の 2.5 se は単発で、IS の標準誤差の範囲を大きく外れるほどではない。

**E と E2**
- median |ΔE − ΔE2| は 0.204、最大は 1.14。v2 は median 0.19 で、ほぼ同じだった。
- 符号の不一致は、主 prior で 2/36（rep03 sparse の列 3 と列 5）、全 prior で 7/324。
- この差は v2 とほぼ同じである。
- **INTERPRETATION:** 数値誤差（S6・S9 で 1e-6 程度）では説明できない。2 つの近似の違い（joint Laplace と nested Laplace）による系統的な差である。
  どちらが厳密な周辺尤度に近いかは、この pilot からは判定できない。

**限界**
- E2 ≈ IS は、外側の f 積分の Gaussian 近似を確かめるだけである。Z の Laplace 誤差は検証していない。
- E2 と IS は同じ被積分関数を使い、提案分布の中心も同じである。

**ラベルを使わない判定状態（主 prior）**
- 36/36 が DECIDED、全 prior では 323/324。
- これは数値上の判定可能性であって、正しさではない。

## 4. 解釈（INTERPRETATION）

- v2 の停止原因は、受理判定の不具合（φ の丸めで Armijo が止まり、log|H| の 1 次の誤差が FD の雑音になった）だった。モデルの病理ではない。
  証明書型の受理で、この原因は pilot の範囲では解消した。
- ただし証明書は、正定値な点での局所的な性質である。Z の大域的な多峰性は、決定的な cold start と救済の記録でしか確かめていない。
- 「数値的に信頼できる」と言えるのは、Laplace 近似 E2 の値を数値誤差 ≪ 0.01 で計算できることまでである。E2 が厳密な周辺尤度に近いことは示していない。

## 5. 独立監査（research-auditor）

読み取り専用の独立監査の結果、BLOCKER は 0、WARNING は 4、NOTE は 5 だった。pilot の出力は「停止規則をすべて通過」を裏づけており、閾値を数値的に緩めた箇所はない。

**WARNING**

1. **v2 定義の S4 は報告値で、停止規則ではない。**
   - v3 の S4（救済の後も失敗）と S4r（救済）は、それぞれ 5% 以下が条件である。
   - そのため、v2 定義の値（両者を合わせたセルの割合）は最大で約 10% まで許される。protocol の「S4r で別に抑える」は、v2 の基準で見ると厳密ではない。
   - 今回は両方とも 0 なので、結果に影響はない。
2. **`certify_outer` の判定漏れ。**
   - 追加の Newton step の点で T が無効なとき、gain が NaN のまま CERT_OK を返す経路がある。
   - 採用した開始点では、648 セルすべてで gain が有限だった。
   - 採用しなかった開始点は gain を記録していないため、確かめられない（UNVERIFIED）。
3. **解析の集計が NaN を飛ばしうる。**
   - S4b〜S9 の集計は、pandas の max / median が NaN を飛ばす。
   - 監査で、対象の列がすべて有限であることを確認した。今回は飛ばされた値はない。
4. **解析の出力に runinfo がない（KI-014）。**
   - 解析の出力（audit JSON など）には、それ自体の runinfo がない。
   - 解析コードは `e183c45` のまま、pilot の後も変更していない（`git diff e183c45` は空）。

さらに、mathematical_notes の 27 行目の数値の誤りを指摘した（§1 で訂正）。
