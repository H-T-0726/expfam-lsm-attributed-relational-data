# AF6 Phase A：AF5 の独立監査

- 作成：2026-11-14
- branch：`experiment/af6-laplace-confirmation`（AF5 の最終 commit `a598bb5` から分岐）
- 新しいデータの生成：なし。MCEM：0 回
- 監査の二つの経路：
  1. **独立監査者**（subagent `research-auditor`、読み取りのみ）。コード、数式、CSV、protocol を照合し、AF5 の結論はそのまま受け入れていません。
  2. **独立した数値の再計算**（`expfam/src/experimental/audit_af6_af5_independent.py`、出力は `phase_a/`）。
     - AF5、AF4、旧来のコード経路を呼ばずに、次を自前で実装しています：
       - 対数同時密度
       - 勾配
       - 完全な負 Hessian（Y の交差ブロックを含む）
       - Z の joint mode（独自の減衰付き Newton 法）
       - log 行列式（固有値から計算）
       - スコア S、Δ、判定状態の規則、主指標、信頼区間
     - CMP(ν=2) の正規化定数は、級数ではなく閉じた形 Σ_k e^{kη}/(k!)² = I₀(2e^{η/2}) を使いました。
     - AF5 と共有したのは入力だけです：生成されたデータ、AF2 の保存 fit、AF5 が報告した f_j*。

## 判定

**WARNING。BLOCKER はありません。**

- 数理と実装には、比較の正当性を損なう問題はありません。
- Laplace 近似の誤差については、次の制限があります：
  - **符号を変えるほどの影響は、ほぼ同点の列に限られます。**
  - ただし、近似を使わない積分（TI）で計算し直すと、**AF5 の sparse の改善（同じ anchor の Q との比較）の 95% 信頼区間が 0 をまたぎます**（§3.3）。
- そのため AF6 では、事前に登録した近似の診断（TI）を全 sparse 列で実行し、Laplace による判定と、近似を使わない marginal による判定を分けて報告します。

## 3. Laplace 近似誤差の監査（最重要）

### 3.1 誤差の切り分け

| 誤差の種類 | 大きさ | 根拠 |
|---|---|---|
| 最適化の誤差（f_j） | \|S の有限差分勾配\|∞ < 1e-5。2 つの開始点の差は ≤ 1e-11 | AF5 の CSV、監査者 |
| mode の誤差 | \|∇\|∞ ≤ 1e-9 | 独立再計算 |
| Hessian と log 行列式の数値誤差 | S の差 ≤ 8e-10 | 独立再計算（固有値と slogdet の比較） |
| **Laplace 近似そのものの誤差** | **sparse で \|Δ_L − Δ_TI\| の中央値 0.12〜0.13、最大 0.49** | §3.2 |

**比べるべきは 4 番目です。** 誤った列の |Δ| の中央値は dense 0.29、sparse 0.68 でした。最適化と数値の誤差は、これより 7 桁以上小さいので問題になりません。

### 3.2 候補間の差を直接推定する方法（熱力学積分、TI）

候補ごとの log marginal を別々に推定するのではなく、**差を直接推定**しました。

```
log p_C − log p_P = ∫₀¹ E_{π_t}[ ℓ_C(x_j | Z f_C*) − ℓ_P(x_j | Z f_P*) ] dt,
π_t(Z) ∝ exp( Φ_P(Z) + t [ℓ_C − ℓ_P] )
```

- 被積分関数には対象の列だけが入ります。ほかの列、Y、事前分布は両候補で共通なので、分散が小さくなります。
- 数値積分は Gauss–Legendre 6 点です。
- 各点で、π_t の Laplace 近似を metric とする白色化した HMC を回しました。
  - ステップ幅 0.3、8 ステップ、2 chain × (150+600)。
  - 受理率の最小値は 0.84 です。
- MC の標準誤差は batch means から求めました（中央値 0.047、最大 0.092）。
- 数値積分の点数を 6 と 12 で比べると、差は ≤ 0.014 で、MC の誤差の範囲内でした（`ti_quadrature_check.csv`）。
- IS が読める dense 列では、TI と IS 補正後の Δ が一致しました（例：rep01 dense 列 4 で −2.41 と −2.45）。差の中央値は 0.049 です。
- **限界**：TI は Laplace で最適化した f* における、Z を積分した marginal の差です。f_j を真の marginal で最適化した profile の最大値とは、2 次の項だけ違います。

対象は、主 anchor の列のうち、Laplace の値だけで決めた 138 列です（正解は見ていません）：

- sparse の全 120 列
- dense で |Δ_L| < 2 の 18 列

### 3.3 結果（`ti_summary.csv`、`ti_sparse_vs_q.csv`）

| regime | IS | 列数 | 符号の一致 | Δ_L − Δ_TI の中央値 | \|·\| の中央値 / 最大 | Laplace の正解率 | TI の正解率 |
|---|---|---|---|---|---|---|---|
| dense（\|Δ_L\|<2） | 読める | 18 | 17 | −0.004 | 0.039 / 0.119 | 0.500 | 0.556 |
| sparse | 読めない | 46 | **46** | −0.124 | 0.132 / 0.407 | 0.870 | 0.870 |
| sparse | 読める | 74 | 72 | −0.119 | 0.123 / 0.492 | 0.851 | 0.824 |

- **OBSERVED：IS で確かめられなかった sparse の 46 列では、Laplace と TI の符号がすべて一致しました。** AF5 の「改善は確かめられない列に偏る」という懸念のうち、「その列では近似が符号を誤っているのではないか」という部分は、この 46 列では否定されました。
- **OBSERVED：sparse の Laplace は、Δ を系統的に約 0.12 小さく見積もります。** つまり Poisson 側にずれます。
  - そのため、|Δ| が 0.5 未満の同点に近い列では、符号が変わり得ます。
  - 実際に符号が変わったのは 3 列で、いずれも真は Poisson、|Δ_L| ≤ 0.19、|Δ_TI| ≤ 0.11 でした。
  - sparse の 2 列（rep10 列 4、rep07 列 5）では、Laplace は正しく Poisson を選び、TI は CMP2 側になりました。ただし、どちらも |Δ_TI| が TI の MC 標準誤差の 2 倍に届かず、TI でも符号は決まりません。
- **OBSERVED：Δ の符号を TI に置き換えて AF5 の sparse 比較を計算し直すと、Q との差は +0.35 [−0.05, 0.70] になり、下限が 0 を下回ります。**
  - Laplace の符号のままなら +0.45 [0.10, 0.75] です。
    - これは 120 列すべてを符号で判定した値です（UNDECIDED_NUMERIC も含みます）。
    - AF5 の「applied」の規則（判定不能の列は AF2 の選択を使う）とは少し違います。
  - 原因は、上の 2 列で正解が誤りに変わったことです。この 2 列は、TI の MC 誤差の範囲内でほぼ同点の列です。
  - **「Laplace 目的関数による改善」と「近似を使わない marginal による改善」は分けて扱う必要があります。** 後者は AF5 の 20 データでは CI が 0 をまたいでいます。
- 解釈（HYPOTHESIS）：Δ の系統的なずれの向き（−0.12）から見ると、近似の誤差で改善が水増しされた可能性は低いと考えます。改善は主に、|Δ| が大きい列（AF2/Q の誤りが CMP2 → Poisson に偏っていた列）から来ているからです。CI が 0 をまたぐのは、主に 20 データという標本の小ささによると考えます。

### 3.4 IS の判定規則について（監査者の指摘）

- 相対 ESS ≥ 0.01 は、2000 draw のうち実効 20 です。batch SE は過小評価の向きにずれ得ます。
- それでも、読めた列で IS と TI を比べると、差の中央値は 0.049、最大は 0.34 でした。補正の向きはおおむね正しいです。
- AF6 では、保守的な方法 D の規則に AF5 の IS の規則をそのまま使います（依頼のとおり）。近似の妥当性は TI で別に評価します。

## 4. AF5 の README の誤記と過大表現（AF5 の成果物は変更せず、ここに記録）

1. **anchor が同じ fit になっている（開示漏れ）**
   - auto_first と oracle の保存状態の sha256 が一致するデータ×regime が 14 あります。dense 10（rep01, 02, 03, 07, 08, 10, 12, 13, 14, 16）、sparse 4（rep07, 12, 13, 16）で、いずれも Auto がすべての列を正しく選んだ場合です。
   - auto と support_only が一致するのは 2 です（rep02 sparse、rep14 sparse）。
   - AF5 §4.6 と §5 D の「auto と oracle の一致率」は、その分だけ構成上の一致を含み、根拠として弱まります。auto と support の一致には、この問題はほとんどありません。
2. **§5 B の論理が逆になっている**
   - 同じ anchor の Q との比較は、「スコアの定義を変えた効果」そのものを測るものです。
   - さらに Laplace は q を使わないので、「同じ q」という表現は誤りです（正しくは「同じ保存 fit」）。
   - この比較は副次の指標で、confident では 0.00 [−0.30, 0.30] でした。§3.3 のとおり、TI で計算し直すと CI は 0 をまたぎます。
3. **§5 E の表現**
   - 「Laplace 近似の誤差は IS 補正より小さく、問題にならない」は論理が成り立っていません。IS 補正そのものが Laplace 誤差の推定値だからです。
   - 正しくは §3.3 の TI の結果です。
4. **§3 の Phase 0 の git の記載**
   - `phase0/phase0_summary.json` の git_head は `69709e5` です。AF5 の runner は未 commit の状態で実行されており、runinfo の dirty 判定は未追跡のファイルを無視していました。
   - Phase 0 のコードが `3dca16f` と同じかどうかは、確かめられません（UNVERIFIED）。
   - pilot と本実行は、commit 済みで dirty=false です。
5. **§4.7 の「常に CMP2 に有利」**：群平均での話で、列単位では成り立ちません（例：rep01 dense 列 5 は −2.3e-5）。
6. **分母の違い**：AF5 の Laplace の正解率は判定できた列（sparse は 119 列）が分母で、Q と AF2 は 120 列が分母です。AF6 では全列を分母にします。

## 5. AF6 に反映すること

- 主指標を 1 つに固定します：sparse の A − B（同じ Auto anchor の Q）の D_r、全列を分母とする。
- anchor は Auto だけにします。oracle と auto が同じ fit になる問題は、AF6 では起きません。
- 近似の診断として TI を事前に登録します：全 sparse 列と、dense で |Δ_L| < 2 の列。結果は次の 3 つを分けて報告します：
  - Laplace の符号による結果
  - TI の符号による結果
  - TI で確かめた列だけの結果
- 方法 D（保守的な方法）は、AF5 の IS 規則（DECIDED）で決め、それ以外の列は Q を使います。
- runinfo に、未追跡の experimental コードの一覧を記録します。Phase B は commit 済みのコードでだけ実行します。
- 列ごとに anchor の分布を記録し、anchor の分布に引き寄せられた誤りの割合を診断します。
