psutil は **A に存在しなかった**。7.2.2 という版は

**過去の実験が psutil 7.2.2 で実行されたことを意味しない。**

### 3.4 構築手順（実行済み・再現可能）

```
python -m pip install uv                      # uv 0.12.5
python -m venv .venv                          # clean venv（Python 3.13.14）
python -m uv pip compile --upgrade requirements.in     -o requirements.txt     --generate-hashes --python .venv/Scripts/python.exe
python -m uv pip compile --upgrade requirements-dev.in -o requirements-dev.txt --generate-hashes --python .venv/Scripts/python.exe
python -m uv pip sync requirements-dev.txt --python .venv/Scripts/python.exe
```

`requirements.txt` / `requirements-dev.txt` は **uv による機械生成**であり、人手で pin していない。
`pip freeze` は使用していない。全パッケージに `--generate-hashes` によるハッシュが付与されている。
`--upgrade` を付けて既存 output の pin を再利用しない fresh resolution とし、
`uv pip sync` により venv と lock を一致させている。

### 3.5 環境構築上の negative result: `uv venv` の失敗

このマシン・この実行において、`uv venv` による venv 作成は次のエラーで失敗した。

```
error: Failed to create virtual environment
  Caused by: failed to copy file from
    C:\Program Files\WindowsApps\PythonSoftwareFoundation.Python.3.13_3.13.3824.0_x64__qbz5n2kfra8p0\Lib\venv\scripts\nt\venvlauncher.exe
    to D:\tento\kennkyu\.venv\Scripts\python.exe:
    指定されたファイルを暗号化できませんでした。 (os error 6000 / ERROR_ENCRYPTION_FAILED)
```

- uv 0.12.5、source は Microsoft Store 版 Python 3.13.14、target は D: ドライブ（NTFS）。
- 対処として venv 作成のみ stdlib の `python -m venv .venv` に fallback した。これは成功した。
- lock の compile / sync は計画どおり uv が実行しており、fallback は venv 作成手順に限られる。

**この記述は今回のマシン・今回の実行で観測された事実に限る。**
一般に `uv venv` が Windows Store 版 Python で失敗する、という一般化は行わない。
原因の切り分け（EFS 属性、ドライブ、uv の copy 方式のいずれに起因するか）は未実施。
