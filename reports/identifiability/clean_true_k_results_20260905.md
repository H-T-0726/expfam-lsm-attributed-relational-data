# clean true-K n-sweep — 結果

本レポートは `expfam/results/k_selection/clean_true_k_asymptotics_20260904/` の artifact から自動生成した（`tools/research_audit/build_clean_true_k_report.py`）。数値の手作業転記は行っていない。
各セルの selected K は per-fit の生値から凍結 selector で**再導出**し、`selection_matrix.csv` と一致することを確認したうえで出力している（不一致なら生成が中断する）。

**このレポート生成では EM を 1 回も実行していない。**

## 0. 何を問うた実験か

> **canonical clean generator による well-specified な有限標本設定で、`n` を増やしたとき、
> 事前登録した各 K-selection criterion の selected-K パターンはどう変わるか。**

**これは consistency theorem ではない。** 有限の `n` を 4 点動かした記述的観測であり、
`n -> infinity` の一致性については何も示さない（理論監査 16b・U6）。

### なぜ historical generator では不十分だったか

一次コードを読んで確認した差分（`true_k_identifiability_hardened_20260904.md` 13、KI-021）:
`Z` と Gaussian-X の事後 z-score、`F` の行正規化、Poisson の hard clip、未使用の `sigma_x_true`。
**過去結果を無効化するものではない**が、「canonical model から well-specified に生成した」という
強い読み方はできない。とくに Poisson-X の識別可能性命題は unclipped link と iid `N(0,I)` を
前提とするため、historical generator ではその前提が成立しない。

### なぜ X=Poisson / Y=Bernoulli を選んだか

- **X=Poisson**: population で `FF^T` をモーメントから復元でき、`K = rank(FF^T)` を議論できる
  唯一の family（理論監査 P1）。ただし確立したのは **X 周辺の最小次元**であり `K*` ではない。
- **Y=Bernoulli**: Phase 7e / 8b との比較可能性のため。**同時に、識別可能性（U2）も
  非入れ子性（U5）も未証明の family** であり、理論的にもっとも弱い場所である。
  P2・P3（強い結果）は Gaussian-Y 限定であって、ここには適用できない。

## 8. 解釈（有限標本の記述的結果のみ）

### 8.1 主要所見

**(1) `K_TRUE = 5`（PRIMARY）:** テストした `n = 50, 75, 100, 150` の範囲で、
S1 の真値一致は 2/8 -> 0/8 -> 4/8 -> 8/8、
平均 selected K は 2.62 -> 3.0 -> 4.5 -> 5.0 と推移した。
S2 は真値一致 0/8 -> 0/8 -> 1/8 -> 7/8、
平均 selected K は 1.75 -> 3.25 -> 3.62 -> 4.88。

**平均 selected K は S1・S2 とも単調に増加したが、真値一致数は単調ではない**
（S1 は n=75 で 0/8 といったん下がる）。**「n を増やすと K=5 に収束した」とは書かない。**
誤りの向きは一貫して **under-selection** であり、over-selection はごく少数である。

**(2) `K_TRUE = 1` の 4/4 は good recovery の証拠ではない。** S1・S2 とも全 `n` で 4/4 だが、
この設定の支配的な誤り方は under-selection であり、`K = 1` は候補集合の**下端**である。
さらに凍結 selector は同点時に最小 K を選ぶ。したがって `K_TRUE = 1` での一致は、
**データからの識別ではなく手続き上の下限効果である可能性を排除できない**（理論監査 17.4）。

**(3) `K_TRUE = 3`（control）:** S1 1/4 -> 1/4 -> 3/4 -> 4/4、
S2 2/4 -> 3/4 -> 4/4 -> 4/4。
`K_TRUE = 5` と同じく under-selection 優位で、`n` とともに一致が増える傾向は共通している。
**`K_TRUE` が大きいほど、同じ `n` で真値一致に届きにくい**という記述的傾向が見える。

**(4) S3（plug-in conditional）は使えない。** 真値一致 3/64 で、
ほぼ全セルで候補上限 `K = 7` を選ぶ。`ln p(Z)` を含めず `Z` を積分しないため、
潜在次元を増やすほど代入した Z への当てはまりが良くなり、`p log n` の罰則が追いつかない。
**これは Q1 型（conditional / plug-in）の基準に対する警告であって、原論文 Eq.(26) の評価ではない。**
原論文の評価手続きは本文から特定不能であり（`paper_bic_reproduction_alignment_20260904.md`）、
**S3 の失敗を原論文の基準の失敗と読んではならない。**

**(5) start 間の不一致が不安定性の指標になっている。** S1 / `K_TRUE=5` では、
2 つの初期値が別々の K を選ぶセルが `n=50` で 8/8、`n=150` で 1/8 だった。
**選択が不安定な領域と、最適化が初期値に依存する領域が一致している。**
これは criterion だけの問題ではなく推定側の多峰性も効いていることを示唆するが、
**どちらが主因かは本実験では分離できていない**（`[UNRESOLVED]`）。

### 8.2 書いてよい表現 / 書いてはいけない表現

**書いてよい:**

> テストした有限の `n` の範囲（50-150）では、held-out 予測スコアと Q ベース基準の
> いずれについても、`n` の増加にともなって平均 selected K が真値へ近づき、
> under-selection が減少する傾向が観測された。ただし真値一致数は単調ではなく、
> 各条件の反復は 4 または 8 のみである。

**書いてはいけない:** 「`n` を増やすと `K_TRUE` に収束した」「K 選択の一致性を示した」
「held-out なら真の K を選べる」「`K_TRUE=1` で完全に回復した」
「S3 の失敗は原論文 BIC の失敗である」。

| 8 | **lineage E（experimental prototype）。本文採用不可** |
| 9 | **1 つの合成設定のみ。** `d=15`、Poisson-X / Bernoulli-Y、信号強度は 1 水準に固定 |

## 10. この実験の claim ledger

### ALLOWED（本実験の証拠で書けること）

- clean generator の設計不変量が全 64 セルで厳密に成立したこと（`rank(F)=K_TRUE`、正規化なし、clip なし、平均 `||f_l||^2 = 0.5`、`w^2 K = 3.0`）
- 実行された fit 数がちょうど 896、retry・replacement・seed rescue・tolerance 緩和・resume がいずれも 0 であること
- 独立 artifact 監査の verdict と finding 件数
- 各 `(criterion, K_TRUE, n, replicate)` の selected K の**正確な値**

### QUALIFIED ONLY（限定語なしに書いてはいけない）

- 「`n` の増加とともに平均 selected K が真値へ近づいた」-> **テストした有限範囲での記述、真値一致数は非単調、反復 4/8 のみ**を必ず併記
- 「S1 と S2 は似た挙動を示した」-> **64 セル中の一致数を明記**
- 「S3 は過大選択した」-> **本モジュールで定義した基準であり原論文の基準ではない**を必ず併記

### NOT ALLOWED

- K 選択の一致性 / 漸近一致性 / universal true-K recovery
- 現行実装が standard Schwarz BIC として妥当であること
- held-out 予測 = true-K recovery
- Bernoulli 一般の識別可能性についての結論
- 本合成設定を超える一般化

## 11. 次に問うべきこと

1. **`K_TRUE=1` の下限効果を切り分ける。** 候補集合の下端を広げるか tie rule を変えた感度解析（**本実験の protocol では変更禁止なので、新しい事前登録が要る**）。
2. **start 不一致が criterion 由来か最適化由来かを分離する。** start 数を増やすか、同一の Z 推定を共有して criterion だけ比較する設計。
