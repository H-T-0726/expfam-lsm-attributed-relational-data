## Slide 2. 従来モデル: 属性付き関係データの潜在構造モデル

- **1 番伝えたいこと**: 各ノードに連続の潜在ベクトル z_i を置き、属性 X と関係 Y を同じ z から説明する。
- **前 slide とのつながり**: slide 1 の「対象」を式にする。
- **本文**:
  - 従来モデル（Mikawa et al. 2024）は X = Gaussian、Y = Bernoulli に固定。
  - 推定は MCEM（E-step は Laplace 近似によるサンプリング）。潜在次元 K は情報量基準で選んでいた。
- **数式**（E1〜E3）:
  ```
  z_i ~ N(0, I_K)
  x_il | z_i ~ N( f_l^T z_i , σ_l² )                  （従来: Gaussian）
  y_ij | z_i, z_j ~ Bernoulli( σ(w0 + w z_i^T z_j) )   i < j
  ```
- **記号の意味**: z_i = ノード i の K 次元潜在ベクトル、f_l = 列 l の loading（F の l 行）、w0 = 関係の全体の密度、w = 潜在構造が関係に効く強さ、σ(·) = ロジスティック関数。
- **表**: なし。
- **図の案**: Figure 1（Z → X、Z → Y のグラフィカルモデル）。
- **実験条件**: なし。
- **強調すべき数値**: なし。
- **口頭補足**: z は連続ベクトルで、クラス番号ではない（後の分布選択の議論で重要）。X 側に切片はない。
- **誤解されやすい点**: w を行列と思われやすい（スカラー）。z を潜在クラスと思われやすい。
- **言ってはいけないこと**: 「W_Y 行列」「z_i はクラスタ」。原論文の BIC を「Schwarz BIC」と言うこと（原論文の Eq.26 の当てはまり項も z に条件づけている: KI-010 D 項）。
- **source**: `RESEARCH_MASTER.md` §2, §4、`CLAUDE.md` §1、KI-010。

## Slide 3. 指数型分布族への拡張

- **本文**:
  - X 側・Y 側で独立に分布族を指定できる。X の尤度は列ごとに因子分解する。
  - 標準実装では X の分布族は全列共通（`family_x` はスカラー）。列ごとに変えるのは prototype（`family_x_list`）だけ。

## Slide 5. 属性分布の自動選択: 比べてよい候補を先に決める

- **1 番伝えたいこと**: 分布族の比較は「同じ基底測度の候補どうし」でしか尤度で比べられない。だから先に観測値の型から候補を機械的に絞る（support gate）。
- **前 slide とのつながり**: slide 4 の ① を始める。まず「何と何を比べてよいか」を決める。
- **本文**:
  - 列ごとに family 変数 c_l を置く（E4）。
  - 連続値の密度と離散値の確率は尺度が違い、単位を変えると Gaussian の対数密度だけが動く → 尤度の大小で比べられない。
  - support gate（尤度を使わない決定的な規則）:
    - 全値が {0,1} → 候補 {Bernoulli, Poisson}（score で決める）
    - 非負整数で 2 以上を含む → Poisson に固定
    - それ以外（非整数・負値を含む） → Gaussian に固定
  - 帰結: 現行の 3 family では、**score による実質的な比較は 0/1 列の Bernoulli vs Poisson だけ**。
- **数式**（E4）:
  ```
  c_l ∈ M_l,     x_il | z_i, c_l = m ~ ExpFam_m( f_l^(m)T z_i ; ψ_lm )
  ```
- **記号の意味**: M_l = 列 l の候補集合（gate が決める）、f_l^(m) = family m のときの loading（family ごとに別）、ψ_lm = family m のパラメータ（Gaussian は σ_l² も含む）。
- **表**: support gate の 3 行表（観測 / 候補 / 決まり方）。
- **図の案**: Figure 2 の前半（列 → gate の 3 分岐）。
- **実験条件**: なし。
- **強調すべき数値**: なし。
- **口頭補足**: 「カウント列を log 変換して Gaussian で扱うか」は分布選択ではなく表現の選択で、尤度では決められない（設計 report §3.3）。今回は扱わない。
- **誤解されやすい点**: 「Gaussian / Bernoulli / Poisson のどれかを全列で尤度比較している」と思われやすい。
- **言ってはいけないこと**: 「3 つの分布を全部自動判定した」「一般的な分布の自動選択を実現した」。
- **source**: 設計 report §2.1, §3、`family_selection.support_gate`（L.204–254）。

## Slide 6. 連続潜在変数の MCEM の上での再定式化

- **1 番伝えたいこと**: E-step の事後サンプルを固定すると、列ごとの family 比較は他の項（Z の事前・Y）と完全に切り離せる。これが「連続 Z の MCEM 上で分布選択が well-posed」の中身。
- **前 slide とのつながり**: slide 5 で「何を比べるか」を決めた。ここで「どう比べるか」を式にする。
- **本文**:
  - 参考にした考え方: Structural EM 型の分布族選択（E-step の後に構造＝分布族を選び直す）。ただし参考資料の基本形は潜在クラスモデル。本研究は z_i ∈ R^K の連続潜在変数なので、**MCEM の事後サンプルを使う形に再定式化**した。
  - 固定した事後サンプルの下で、Q 関数は Q_Z + Σ_l Q_l + Q_Y と分かれ、Q_Z と Q_Y は c に依存しない。
  - 比較には各分布の「完全な」対数確率を使う（Poisson の −log(x!)、Gaussian の −½ log 2π を落とさない）。
  - loading は候補 family ごとに別々に最適化する（link が違うので最適な f_l も違う）。
- **数式**（E5, E6）:
  ```
  Q_l(m, ψ_lm | q_t) = (1/L) Σ_{s=1}^{L} Σ_{i=1}^{n} log p_m( x_il | f_l^(m)T z_i^(s) ; ψ_lm ),   Z^(s) ~ q_t(Z)
  ĉ_l = argmax_{m ∈ M_l} Q_l(m, ψ̂_lm | q_t)
  ```
  完全な対数確率: Bernoulli `xη − log(1+e^η)`、Poisson `xη − e^η − log(x!)`、Gaussian `−(x−η)²/(2σ²) − ½ log σ² − ½ log 2π`。
- **記号の意味**: q_t = 反復 t の E-step のサンプラーの分布、Z^(s) = その L = 5 本のサンプル、ψ̂_lm = 候補 m で最適化したパラメータ。
- **表**: 3 family の完全対数確率の表（どの項が比較に必要か）。
- **図の案**: Q の分解を色分けした式（Q_Z・Q_Y はグレー、Q_l だけ強調）。
- **実験条件**: なし。
- **強調すべき数値**: L = 5。
- **口頭補足**: 0/1 列では log(x!) = 0 なので偶然消えるが、比較の式としては残す。参考資料（外部 PDF）は今回の監査では読めていない（EXTERNAL_PDF_STATUS: NOT_AVAILABLE_TO_CLAUDE）ので、その式は引用しない。
- **誤解されやすい点**: 「参考資料の手法をそのまま実装した」。「EM 全体として観測データ尤度が単調に増える」。
- **言ってはいけないこと**: 上の 2 つ。q_t を真の事後と呼ぶこと。
- **source**: 設計 report §1, §2.2–2.4, §4、`family_selection.column_log_likelihood`（L.284–335）、`select_from_records`（L.707–734）。

## Slide 7. 選択アルゴリズム: 探索 → 固定 → 新規 refit

- **1 番伝えたいこと**: 探索中に family を更新し、最後に family を固定してもう一度ゼロから推定し直す（hybrid）。報告する値は「固定した family での普通の推定」になる。
- **前 slide とのつながり**: slide 6 の選択規則を、推定の手順の中に置く。
- **本文**:
  1. support gate で各列の候補を決める。
  2. 探索 MCEM: 各反復の M-step で、0/1 列について Bernoulli・Poisson の両方の loading を最適化し score が大きい方を選ぶ（選ばれた候補の loading をそのまま使う）。
  3. 最終反復の割り当てを固定する。
  4. 固定した割り当てで MCEM を新しく実行し直し（refit）、その結果を報告する。
  - 選択の差（margin）は記録するが、離散的な選択のコストは罰則に入れていない。
- **数式**: E6（再掲）と margin `[−2Q_l(次点)] − [−2Q_l(ĉ_l)]`。
- **記号の意味**: margin = 次点がどれだけ悪いか（−2 × score の単位）。
- **表**: 3 方式（EM 内更新 / 全組合せ比較 / hybrid）の比較を 1 行ずつ（全組合せは 2^d 通りで非現実的、hybrid は報告値の由来が明確）。
- **図の案**: Figure 2（family 選択のフロー）。
- **実験条件**: BFGS（解析勾配）、収束判定 grad_inf ≤ 1e-8 は診断用。
- **強調すべき数値**: なし。
- **口頭補足**: refit を挟むのは、探索経路に依存した数値を報告しないため（再現性・監査性）。
- **誤解されやすい点**: 「hybrid の周回を収束まで繰り返した」（1 回だけ）。
- **言ってはいけないこと**: 「方式 C が理論的に最適」。「離散探索の罰則を正しく扱った」。
- **source**: 設計 report §6.4, §7、`family_selection.run_family_exploration`（L.1048–1191）、`run_hybrid_family_selection`（L.1194–1294）。

## Slide 8. 分布選択の実験: 0/1 列 36/36

- **1 番伝えたいこと**: 易しい側の 1 条件で、仕組みは最後まで動き、score で決めた 0/1 列（真は Bernoulli）を 36/36 で正しく選んだ。開始点に依存しなかった。

## Slide 11. 現行基準 C_Q の正体

- **1 番伝えたいこと**: 現行基準 C_Q は Schwarz BIC ではない。Z を積分した尤度ではなく、Z の事前密度を含む完全データの Q 関数に基づく Q 型・ICL 型の基準で、その中に 1 次元あたり一定の項 P_Z = n(1 + ln 2π) が入っている。
- **前 slide とのつながり**: slide 10 の「一定の罰則」の出どころを式で示す。
- **本文**:
  - C_Q = −2 × Q_strict + パラメータ数 × ln n。Q_strict は EM の Q 関数（E-step サンプルでの完全データ対数尤度の平均）。
  - 3 つに分解できる: 当てはまり D_K、Z の事前の項 P_Z、パラメータ罰則 P_θ。
  - 推定中に Z を平均二乗 1 に揃える（scale_Z）ので、P_Z は厳密に nK(1 + ln 2π)。n = 75 なら 1 次元あたり 212.84。
  - 構造としては「観測データ型 BIC + 2 × 潜在変数の事後エントロピー」と同じ形 → ICL 型。ただし連続 Z のエントロピーは尺度に依存する。
- **数式**（E8〜E10）:
  ```
  C_Q(K) = −2 Q_strict(K) + p_K ln n
  C_Q = D_K + P_Z + P_θ,   D_K = −2(Q_X + Q_Y),   P_Z = −2 Q_Z,   P_θ = p_K ln n
  P_Z = nK (1 + ln 2π)     （n = 75: 1 次元あたり 212.84）
  p_K = K d − K(K−1)/2 + （Gaussian 列の数）
  ```
- **記号の意味**: Q_X, Q_Y, Q_Z = Q 関数の X・Y・Z の事前の部分、p_K = パラメータ数（回転の自由度を引いた loading の数 + Gaussian 列の分散）。
- **表**: 9D rep2 の分解（K = 1..5 の D_K / P_Z / P_θ / C_Q）を 1 例として。P_Z の列が 212.84 × K で一定なのが一目で分かる。
- **図の案**: Figure 4 の左半分（C_Q の積み上げ棒: D_K・P_Z・P_θ）。
- **実験条件**: 理論＋既存 artifact の分解（新しい実験ではない）。
- **強調すべき数値**: **212.84 / 次元**、分解の再構成残差 ≤ 1.8e-12。
- **口頭補足**: P_Z の係数は「事前分散を 1 とする」という慣行で決まり、観測データからは識別できない（Z の尺度を変えると C_Q は nK ln σ² ずれる）。関数名は歴史的に `bic` だが、Phase 9 の実装は `calc_bic_exp`。
- **誤解されやすい点**: 「P_Z は誰かが意図的に入れた罰則」。「BIC と書いてあるから BIC」。
- **言ってはいけないこと**: 「C_Q は Schwarz BIC」「P_Z が過小選択の原因」「C_Q は間違った基準」。
- **source**: `cq_decomposition_minimal_check_20260923.md`、`cq_theoretical_clarification_20260927.md` §2–4、`eval_utils.calc_bic_exp`、`reproduction/src/model.py` `scale_Z`、KI-010（provenance: #72 / Phase 9F）。

## Slide 12. Candidate B: Z を積分する基準 C_Lap

- **1 番伝えたいこと**: 目標を「真の K を回復すること」とするなら、Z を積分した観測データの尤度（evidence）を使うのが自然。それを Laplace 近似し、θ には BIC 型の罰則を付けた基準 C_Lap を作った。固定の P_Z が、データで決まる「体積」に置き換わる。
- **前 slide とのつながり**: slide 11 で C_Q が Z を積分していないことが分かった → 積分する版を作る。
- **本文**:
  - Z の同時最頻値 Ẑ（nK 次元）と同時 Hessian H（nK × nK、関係 Y によるノード間の非対角ブロックを含む）で Laplace 近似。
  - 4 つの項: データの当てはまり、Z の事前の寄与、Laplace の体積、θ の罰則。
  - 実装の確認: 勾配と同時 Hessian が有限差分と約 1e-9 で一致、Laplace が厳密になる場合（Gaussian-X・w = 0）に厳密な周辺尤度と一致、潜在尺度を変えても値と K 間の差が不変。停留条件（|∇| ≤ 1e-8）と H の正定値を満たさないときは値を返さない。
- **数式**（E11）:
  ```
  C_Lap(K) = −2[ℓ_X(Ẑ) + ℓ_Y(Ẑ)] + ‖Ẑ‖² + ln|H(Ẑ)| + d_K ln N
  d_K = K d − K(K−1)/2 + n_gaussian_selected,   N = n = 75（working convention）
  ```
- **記号の意味**: Ẑ = ∇_Z log p(Z, X, Y | θ̂) = 0 を満たす同時最頻値、H = その点での負の Hessian、ℓ_X, ℓ_Y = Ẑ での X・Y の対数尤度、d_K = パラメータ数（現条件では C_Q の p_K と一致）。
- **表**: C_Q と C_Lap の項の対応表（当てはまり: MC 平均 ↔ 同時最頻値、Z の項: 一定の P_Z ↔ データ依存の ‖Ẑ‖² + ln|H|、θ 罰則: 同じ）。
- **図の案**: Figure 4（C_Q と C_Lap の概念的な分解の並置）。
- **実験条件**: 実装確認は小データ（n = 6〜8）の zero-EM テスト。
- **強調すべき数値**: 有限差分一致 **~1e-9**（検証 report の測定値、テスト許容値 1e-6）、厳密値との差 **1.4e-14**。
- **口頭補足**: θ̂ は 8 反復の MCEM の出力で、ℓ_Lap の最大化点ではない（停留性の診断で確認済み、appendix A1）。重点サンプリングで近似誤差を測ろうとしたが重みが退化し、厳密な周辺尤度は得られていない。
- **誤解されやすい点**: 「C_Lap は周辺尤度そのもの」。「Laplace は厳密」。
- **言ってはいけないこと**: 「厳密な周辺尤度」「一致性をもつ」「C_Lap は C_Q より正しい基準」。
- **source**: `k_true_criterion_design_comparison_20260928.md` §3、`laplace_evaluator_zero_em_verification_20260928.md`、`laplace_k_criterion.py`、`run_laplace_pilot.d_K`、`laplace_theta_penalty_theory_20260928.md`（provenance: Phase 9G / 9H / 9L）。

## Slide 16. K=3 と K=4 の境界で何が釣り合っているか

- **1 番伝えたいこと**: K_true = 4 の 10 dataset で、K4 が K3 に勝つかは「当てはまりの改善 vs 罰則側の増分」の釣り合いで決まる。C_Q では罰則側が一定の 251.70 で、それを超えたのは 1/10。C_Lap では罰則側（体積）がデータで変わり、8/10 で改善が上回った。
- **前 slide とのつながり**: slide 15 の K_true = 4 の過小選択を、既存の数値だけで分解する（新しい推定はしない）。
- **本文**:
  - 差 Δ34 = C(K=4) − C(K=3)。負なら K4、正なら K3。
  - C_Q: 当てはまりの改善（MC 平均）> P_Z の増分 212.84 + パラメータ罰則の増分 38.86 = 251.70 なら K4。
  - C_Lap: 当てはまりの改善（同時最頻値）> 体積の増分 Δ(‖Ẑ‖² + log|H|) + 38.86 なら K4。
  - 同じ fit でも、当てはまりの改善の値自体が基準で違う（median 164.6 vs 254.8）。
  - 再構成は 10/10 で誤差 1.6e-12 以内。
- **数式**（E12, E13）:
  ```
  Δ34_Q   = −fit_gain_Q_34   + 212.84 + 38.86
  Δ34_Lap = −fit_gain_Lap_34 + Δ(‖Ẑ‖² + log|H|) + 38.86
  margin  = fit gain − (罰則側の増分)      正なら K4 が良い
  ```
- **記号の意味**: fit_gain_Q_34 = D_3 − D_4（MC 平均の当てはまり）、fit_gain_Lap_34 = 同時最頻値での当てはまりの差、38.86 = 9 ln 75（loading が 33 → 42 で 9 増える）。
- **表**: Table G-1（median と正の数）。質疑用に G-2（dataset ごと）。

## Research story audit（自己レビュー）

### A. 分布自動選択 → 同時選択

- **つながり**: 分布選択は K = 3 固定で feasibility を確認した（slide 8）。K を人が決めたままでは「データから選ぶ」が半分しか達成されないので、K も選ぶ。family と K は互いに依存する（loading・Gaussian 列数が K で変わりうる）ので、K ごとに分布選択をやり直すのが自然（slide 9）。
- **飛躍の有無**: なし。ただし slide 8 の 36/36 と slide 9 の 36/36 は別 dataset なので合算しない。
- **補強すべき点**: slide 8 で「K を固定した理由」（機構の feasibility を K 選択と切り離すため）を一言入れる。

### B. 同時選択 → 基準の検討

- **つながり**: 同時選択で 1 dataset が K = 2。これだけでは基準を疑う根拠にならない。そこで (i) 同条件 20 dataset で K = 2 が繰り返し起きること（3/20）、(ii) K2→K3 の判定がデータ非依存の一定の罰則（256.02、うち P_Z 212.84）と当てはまりの比較だけで決まっていること、を確認した（slide 10）。(ii) が「この一定の項は何か」という理論の問いを生む。
- **飛躍の有無**: 小さな飛躍があり得る —「K = 2 が 15% 起きる」ことは基準が悪い証拠ではない。資料では動機を「基準が何を測っているかを確認する必要が生じた」に留め、「基準が間違っていた」とは言わない（slide 10 の「言ってはいけないこと」に明記済み）。
- **補強すべき点**: slide 10 で、検討の根拠は再現性の観測 + 罰則が一定という構造（理論の問い）の 2 つで、K = 2 の 1 件ではないことを口頭で明言する。

### C. 基準の検討 → Candidate B

- **つながり**: C_Q は Z を積分していない Q 型・ICL 型で、P_Z は complete-data を評価した帰結として現れ、係数は観測から識別できない慣行（事前分散 1）に依存する（slide 11）。K 選択の目標を「真の K の回復」に置くなら、Z を積分した観測データの evidence が対応する量で、尺度不変性も持つ → その Laplace 近似として C_Lap（slide 12）。
- **飛躍の有無**: 「目標を真の K の回復とする」は設計上の選択（Phase 9G の判断）であり、別の目標（予測、ICL 的なクラスタの明確さ）なら別の基準もあり得る。また Candidate A（原論文型）・C（ELBO 型）も検討して B を選んだ経緯がある。資料では「目標を真の K の回復に置いた場合の候補」と限定する。
- **補強すべき点**: slide 12 に「なぜ B か」を 1 行（観測データの evidence に対応、尺度不変、本研究の規模で同時 Hessian が計算可能）。A・C の比較は appendix に回す。

### D. Candidate B → 感度 → K_true → 境界の分解

- **つながり**: ベースライン 1 条件で 2 基準の違いを観測（slide 13）→ 違いが信号の強さでどう変わるかを Y 側・X 側で見る（slide 14）→ すべて K_true = 3 だったので真の次元を変える。そのとき信号の強さも変わるので平均量を揃える（slide 15）→ K_true = 4 の過小選択を、新しい推定なしで基準の算術に分解する（slide 16）。
- **飛躍の有無**: (1) slide 14 の 2 つの感度実験は別のデータ系列で、Y 側は「揃えない版 → 揃えた版」と 2 段ある。資料では揃えた版を主にし、揃えない版は「平均密度も変わってしまったので揃えた」という理由づけにだけ使う。(2) slide 16 は分解であって原因ではない。「だから次は原因を分ける実験」は slide 19 の判断事項として提示し、結論にしない。
- **補強すべき点**: slide 15 の冒頭で「K_true を変えると信号の強さも変わる」問題を明示しないと、揃えた設計の意味が伝わらない。slide 16 で C_Q の K1・K2 選択（6/10）が分解の範囲外であることを明示する。

### 全体の判定

- 中心ストーリー（拡張 → 人が決める部分 → 分布選択 → 同時選択 → 基準の疑問 → 基準の正体 → C_Lap → 比較 → 感度 → K_true → 境界 → 分かったこと / 言えないこと）は、上の補強を入れれば**論理的な飛躍なしにつながる**。
- 最大のリスクは B（K = 2 の 1 件から基準批判に跳ぶように見える）と D の結論部分（分解を原因と読ませる）。どちらも slide の「言ってはいけないこと」と口頭補足で対処済み。
- Phase 番号は source 欄だけに残し、本編の見出し・図・表には出していない。
